# UI 스타일 규칙

크기와 색은 화면마다 따로 맞추지 않는다. 기준값을 정하고, 거기서 파생해서 쌓아 올린다.

## 원칙

- 크기를 바꾸려면 컴포넌트가 아니라 기준값을 고친다.
- 컴포넌트에 px 값을 직접 쓰지 않는다. 변수나 변수의 배수를 쓴다.
- 새 크기가 필요하면 먼저 기존 값의 배수로 표현할 수 있는지 본다. 안 되면 기준값에 추가하고 이 문서에 적는다.

## 기준값

크기의 원본은 `src/ui/theme.ts` 한 곳이다. `applyTheme()`이 시작할 때 CSS 변수로 내보낸다.

| 값 | 정의 | 결과 | CSS 변수 |
|---|---|---|---|
| 유닛 | 기준 | 8px | `--u` |
| 슬롯 | 6.5유닛 | 52px | `--slot` |
| 기계 창 너비 | 60유닛 | 480px | `--machine-window` |
| 노드 너비 | 22유닛 | 176px | `--node-w` |
| 노드 높이 | 12유닛 | 96px | `--node-h` |
| 기계 글자 | 고정 | 6px | `--glyph-machine` |
| 아이콘 글자 | 고정 | 4px | `--glyph-icon` |

`src/style.css`의 `:root`에서 파생하는 값:

| 값 | 정의 |
|---|---|
| `--gap` | 1유닛 |
| `--gap-sm` | 0.5유닛 |
| `--gap-lg` | 1.5유닛 |
| `--control` | 4유닛, 버튼 최소 높이 |

글자 크기는 `--text-xs`, `--text-sm`, `--text-md`, `--text-lg` 네 단계만 쓴다.

## 색

색은 역할로 쓴다. 값은 `src/style.css`의 `:root`에 있다.

| 변수 | 역할 |
|---|---|
| `--bg`, `--panel` | 바닥, 패널 |
| `--line` | 테두리 |
| `--fg`, `--dim`, `--faint` | 글자 강도 |
| `--fire` | 가동 중 |
| `--alert` | 멈춤, 경고 |
| `--go` | 조작 가능 |

아이템 색은 `data/display.json`에 있다. 광석은 실제 광물의 색을 따른다.

## 글꼴

- 화면 글자는 도트 글꼴 GalmuriMono11(OFL, `src/assets/fonts`)을 쓴다. 이 글꼴은 12px과 그 두 배에서만 또렷하므로 글자 크기는 12px(`--text-xs`, `--text-sm`, `--text-md`)와 24px(`--text-lg`) 둘뿐이다. 강조는 크기 대신 굵기와 색으로 한다.
- 지도 캔버스도 12px 같은 글꼴로 그린다.
- 기계 그림, 아이템 아이콘, 광맥 그림 같은 글자 그림은 2~6px 글자라 도트 글꼴이 들어갈 자리가 없다. 이것들은 `--art-mono`(JetBrains Mono)로 그린다.

## 글자 그림

- `charGrid(칸 크기, 글자 크기)`가 칸에 들어가는 글자 수를 계산한다.
- 기계 그림은 PixiJS로 그린다. 프레임마다 글자 그림을 한 번만 찍어 텍스처로 두고, 이후에는 텍스처만 바꾼다. Pixi는 기계 창을 처음 열 때 켠다.
- 아이템 아이콘은 `src/ui/iconSprites.ts`의 형태를 쓴다. 명암 단계만 저장하고, 글자와 색은 출력할 때 입힌다.
- 금속 부품은 형태 하나를 공유하고 금속 색만 바꾼다. 음식은 조리 전후로 같은 형태에 색만 바꾼다.
- 금속은 둥근 문자(`# X % o :`), 나머지는 빽빽한 문자(`@ # % * +`)를 쓴다.
- 광석과 슬래그는 저장된 형태 대신 거친 덩어리를 그때그때 그려서 밝기별 글자로 찍는다. 광물 입자가 보이는 질감을 내기 위해서다. 슬래그에는 기포 구멍을 더한다.

## 슬롯

슬롯은 모든 곳에서 같은 컴포넌트를 쓴다.

- 가운데: 아이템 글자 그림
- 오른쪽 위: 아이템 코드
- 오른쪽 아래: 개수
- 비어 있는 입력 칸: 넣을 재료의 그림을 흐리게 표시

## 스크롤바

스크롤바는 쓰지 않는다. 페이지는 창 크기에 고정한다.

- 기지 화면은 빈 곳을 끌어서 둘러본다.
- 긴 목록은 여러 열로 펼친다.
- 그래도 넘치는 목록은 쪽 넘김을 쓴다.

## 성능

- 지도는 DOM 칸이 아니라 canvas 하나로 그린다.

- 화면 갱신은 게임 계산 주기와 같은 초당 10번이다. `requestAnimationFrame`으로 매 프레임 다시 그리지 않는다.
- 값이 바뀌었을 때만 DOM을 건드린다. 지도와 기계 그림은 상태 키가 같으면 다시 그리지 않는다.
- 드래그처럼 입력에 바로 반응해야 하는 동작만 즉시 그린다.

## 툴팁

브라우저 기본 `title`은 쓰지 않는다. 지연을 줄일 수 없기 때문이다. 요소에 `data-tip`을 달면 `src/ui/tooltip.ts`가 즉시 표시한다.

## 창

- 기지 화면은 설비 목록을 보여 준다. 이름을 클릭하면 그 설비의 창이 열린다.
- 창은 한 번에 하나만 열린다. 인벤토리 클릭은 열린 창으로만 들어간다.
- 현재 위치의 화면만 보인다. 기지 밖에서는 기지 화면이 보이지 않는다.
